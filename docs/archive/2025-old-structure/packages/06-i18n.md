> **Version:** 1.0.0

The `@xala/i18n` package provides comprehensive internationalization support for the Xala/Digilist Platform.

## Quick Start

### 1. Choose Your Provider

#### Option A: Standard Provider (Sync Loading)

```tsx
import { I18nProvider, useT } from '@xala/i18n';

function App() {
  return (
    <I18nProvider locale="nb">
      <MyComponent />
    </I18nProvider>
  );
}

function MyComponent() {
  const t = useT();
  return <h1>{t('dashboard.title')}</h1>;
}
```

#### Option B: Lazy Provider (Async Loading) ✨ Recommended

```tsx
import { LazyI18nProvider, useLazyT } from '@xala/i18n';

function App() {
  return (
    <LazyI18nProvider 
      locale="nb"
      fallbackLocale="nb"
      loadingFallback={<Spinner />}
    >
      <MyComponent />
    </LazyI18nProvider>
  );
}

function MyComponent() {
  const t = useLazyT();
  return <h1>{t('dashboard.title')}</h1>;
}
```

### 2. Add Translations

```ts
// packages/i18n/src/locales/nb.ts
export const nb: Record<string, string> = {
  'myFeature.title': 'Min tittel',
  'myFeature.description': 'Min beskrivelse',
};

// packages/i18n/src/locales/en.ts
export const en: Record<string, string> = {
  'myFeature.title': 'My Title',
  'myFeature.description': 'My description',
};
```

### 3. Rebuild & Verify

```bash
pnpm -F @xala/i18n build
pnpm i18n:check
```

## Translation Key Format

### Flat Key Structure

Keys use dot notation but are stored as flat strings:

```ts
// ✅ Correct - Flat keys with dot notation
export const nb: Record<string, string> = {
  'common.save': 'Lagre',
  'common.cancel': 'Avbryt',
  'dashboard.title': 'Dashboard',
  'dashboard.welcomeBack': 'Velkommen tilbake, {{name}}!',
};
```

### Interpolation

Use `{{paramName}}` syntax:

```tsx
// Translation
'greeting': 'Hei, {{name}}! Du har {{count}} meldinger.'

// Usage
t('greeting', { name: 'Ola', count: 5 })
// → "Hei, Ola! Du har 5 meldinger."
```

## CI/CD Integration

### Validation Scripts

```bash
# Check key parity (nb ↔ en)
pnpm i18n:check

# Strict mode (convention warnings fail)
pnpm i18n:check:strict

# Find unused keys
pnpm i18n:unused

# Scan for hardcoded strings
pnpm i18n:scan apps/minside/src

# Analyze legacy keys for migration
pnpm i18n:migrate
```

### Pre-commit Hook

Configured via Husky (`.husky/pre-commit`):

1. Detects translation file changes
2. Runs `pnpm i18n:check`
3. Scans modified app files for hardcoded strings
4. Blocks commit if validation fails

### GitHub Actions

The `i18n-compliance` job runs on every push/PR:

```yaml
i18n-compliance:
  steps:
    - run: pnpm i18n:check
    - run: pnpm -F @xala/i18n test
    - run: node scripts/scan-i18n.js apps/
```

## Performance

### Bundle Sizes

| Component | Size |
|-----------|------|
| Core translations | ~2KB |
| Each locale (nb/en) | ~64KB |
| Formatters & utilities | ~4KB |
| **Total (LazyI18nProvider)** | **~70KB** |
| **Total (I18nProvider)** | **~130KB** |

### Optimization Tips

1. **Use `LazyI18nProvider`** - Only loads active locale
2. **Preload on hover** - Call `preloadLocale()` on language switcher hover
3. **Remove unused keys** - Run `pnpm i18n:unused` monthly
4. **Use shared keys** - Prefer `common.*` over duplicate keys

## Troubleshooting

### Missing Translation Warning

```
Missing translation key: my.key.here
```

**Solution:** Add key to both `nb.ts` and `en.ts`.

### Key Parity Check Failing

```
❌ Key "feature.text" exists in nb but missing in en
```

**Solution:** Add the missing key to the other locale.

### Pre-commit Hook Failing

```bash
# Run checks manually
pnpm i18n:check

# View detailed errors
node scripts/check-i18n-keys.js --json
```

### Build Failing

```bash
# Check TypeScript errors
pnpm -F @xala/i18n typecheck

# Rebuild
pnpm -F @xala/i18n build
```
