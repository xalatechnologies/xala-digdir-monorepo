## 🎯 **Quick Start**

### **1. Make Schema Changes**
```bash
cd packages/database-schema
# Edit src/entitlements.ts
```

### **2. Generate Migration**
```bash
pnpm db:generate
# ✓ Your SQL migration file ➜ migrations/0001_*.sql 🚀
```

### **3. Copy to API**
```bash
cp migrations/0001_*.sql ../../apps/api/drizzle/
```

### **4. Run Migration**
```bash
cd ../../apps/api
pnpm db:migrate
```

### **5. Import Seed Data**
```bash
cd ../../packages/database-schema
export DATABASE_URL="postgresql://user:pass@host:port/db"
pnpm seed
```

## 🔄 **Complete Workflow**

### **Scenario 1: Add New Table**

```bash
# 1. Edit schema
cd packages/database-schema
vim src/entitlements.ts

# Add new table:
export const newTable = saasSchema.table('new_table', {
  id: uuid('id').primaryKey().defaultRandom(),
  name: varchar('name', { length: 255 }).notNull(),
});

# 2. Generate migration
pnpm db:generate
# Creates: migrations/0001_add_new_table.sql

# 3. Copy to API
cp migrations/0001_*.sql ../../apps/api/drizzle/

# 4. Run migration
cd ../../apps/api
pnpm db:migrate
```

### **Scenario 2: Add Column to Existing Table**

```bash
# 1. Edit schema
cd packages/database-schema
vim src/entitlements.ts

# Add column to existing table:
export const routePolicies = saasSchema.table('route_policies', {
  // ... existing columns
  priority: integer('priority').default(0).notNull(),
});

# 2. Generate migration
pnpm db:generate
# Creates: migrations/0002_add_priority_column.sql

# 3. Copy and run (same as above)
```

### **Scenario 3: Update Seed Data**

```bash
# 1. Edit seed data
cd packages/database-schema
vim seeds/route-policies.json

# Add new route:
{
  "app": "backoffice",
  "routeKey": "backoffice.new_feature",
  "requiredRoles": ["TENANT_ADMIN"],
  "requiredModules": ["NEW_MODULE"],
  "requiredFeatures": [],
  "isPublic": false,
  "description": "New feature page"
}

# 2. Import seeds
export DATABASE_URL="postgresql://..."
pnpm seed
# ✅ Idempotent - safe to run multiple times
```

## 🚀 **Deployment Checklist**

### **Pre-Deployment**
- [ ] Schema changes committed
- [ ] Migration generated and tested locally
- [ ] Seed data updated (if needed)
- [ ] Package built successfully
- [ ] Migration copied to API

### **Deployment Steps**

**1. Deploy Migration:**
```bash
ssh root@api.digilist.no
cd /var/www/xala-api
export DATABASE_URL="postgresql://..."
pnpm db:migrate
```

**2. Import Seed Data:**
```bash
cd /var/www/xala-api
# Copy seed files from package
pnpm db:seed:entitlements
```

**3. Verify:**
```bash
psql -d digilist -c "SELECT COUNT(*) FROM saas.route_policies;"
psql -d digilist -c "SELECT COUNT(*) FROM saas.nav_policies;"
psql -d digilist -c "SELECT COUNT(*) FROM saas.plan_entitlements;"
```

## 🎓 **Best Practices**

### **Schema Changes**
1. Always test locally first
2. Generate migration immediately after schema change
3. Review generated SQL before deploying
4. Keep migrations small and focused

### **Seed Data**
1. Use descriptive keys (e.g., `backoffice.bookings.create`)
2. Keep JSON formatted and readable
3. Document complex policies with descriptions
4. Test seed import locally before production

### **Version Control**
1. Commit schema and migration together
2. Never edit generated migrations manually
3. Tag releases with migration numbers
4. Document breaking changes

## 🐛 **Troubleshooting**

### **Migration Generation Hangs**
```bash
# Check schema file size
wc -l src/entitlements.ts
# Should be < 200 lines

# If too large, split into multiple files
```

### **Build Fails**
```bash
# Clean and rebuild
rm -rf dist node_modules
pnpm install
pnpm build
```

### **Seed Import Fails**
```bash
# Check database connection
psql $DATABASE_URL -c "SELECT 1;"

# Check if plans exist
psql $DATABASE_URL -c "SELECT id, name FROM saas.plans;"

# Run with verbose logging
DEBUG=* pnpm seed
```
