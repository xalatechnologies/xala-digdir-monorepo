# Best Practices (God Praksis)

This guide follows the best practices established by [Designsystemet](https://designsystemet.no/no/best-practices) and adds specific guidelines for the Xala platform.

## User Insight (Brukerinnsikt)

### Understanding Digitally Vulnerable Users

When building public services, consider users who may be digitally vulnerable:

- **Elderly users** - May need larger text, simpler navigation
- **Users with disabilities** - Require screen reader support, keyboard navigation
- **Non-native speakers** - Need clear, simple language
- **Low digital literacy** - Require intuitive interfaces

> Reference: [Brukergrupper som er digitalt sårbare](https://designsystemet.no/no/best-practices/user-insight/user-groups-that-are-digitally-vulnerable)

### ResearchOps Best Practices

Structured user research improves product quality:

1. **Centralize research data** - Use shared repositories
2. **Standardize methods** - Consistent interview guides
3. **Share insights** - Cross-team learning

> Reference: [ResearchOps: Nøkkelen til effektiv brukerinnsikt](https://designsystemet.no/no/best-practices/user-insight/researchops)

## Accessibility (Tilgjengelighet)

### Vision Impairment Considerations

Between 7-10% of the population lives with visual impairment:

```tsx
// Ensure sufficient contrast
<Text style={{ color: 'var(--ds-color-text-default)' }}>
  Always use semantic color tokens
</Text>

// Provide text alternatives
<Button aria-label="Close dialog">
  <XMarkIcon aria-hidden="true" />
</Button>

// Support zoom and text scaling
<div data-size="lg">
  {/* Content scales with user preferences */}
</div>
```

> Reference: [Forstå synsnedsettelse](https://designsystemet.no/no/best-practices/accessibility/understanding-vision-impairment)

### WCAG 3.0 Contrast

The upcoming WCAG 3.0 proposes improved contrast calculation (APCA):

```tsx
// Use DS color tokens - they're designed for accessibility
<div style={{
  backgroundColor: 'var(--ds-color-surface-default)',
  color: 'var(--ds-color-text-default)',
}}>
  {/* Guaranteed accessible contrast */}
</div>
```

> Reference: [WCAG 3.0 foreslår ny kontrastmetode](https://designsystemet.no/no/best-practices/accessibility/contrast)

## Content Work (Innholdsarbeid)

### Writing Advice (Skriveråd)

Clear, user-friendly text improves usability:

```tsx
// Good - Clear and direct
<Button>Send søknad</Button>

// Bad - Vague
<Button>Klikk her</Button>

// Good - Actionable
<Alert>
  <Heading>Feil i skjemaet</Heading>
  <Paragraph>Rett feilene markert under for å fortsette.</Paragraph>
</Alert>

// Bad - Unclear
<Alert>
  <Heading>Feil</Heading>
  <Paragraph>Noe gikk galt.</Paragraph>
</Alert>
```

> Reference: [Skriveråd](https://designsystemet.no/no/best-practices/content-work/writing-advice)

### Microtexts (Mikrotekster)

Consistent punctuation in UI elements:

| Element | Punctuation | Example |
|---------|-------------|---------|
| Button labels | No period | `Lagre`, `Avbryt` |
| Field labels | No period | `E-post`, `Fullt navn` |
| Placeholder text | No period | `Skriv her...` |
| Error messages | Period | `E-postadressen er ugyldig.` |
| Help text | Period | `Passordet må ha minst 8 tegn.` |
| Headings | No period | `Mine bookinger` |

> Reference: [Tegnsetting i mikrotekster](https://designsystemet.no/no/best-practices/content-work/microtexts)

### Common Terms (Vanlige begreper)

Use consistent terminology:

| Norwegian | English | Usage |
|-----------|---------|-------|
| Lagre | Save | Primary save action |
| Avbryt | Cancel | Cancel/close action |
| Slett | Delete | Delete action |
| Rediger | Edit | Edit action |
| Legg til | Add | Add new item |
| Søk | Search | Search action |
| Logg inn | Log in | Authentication |
| Logg ut | Log out | Sign out |
| Send | Submit | Form submission |
| Neste | Next | Wizard step |
| Forrige | Previous | Wizard step |
| Fullfør | Complete | Final step |

> Reference: [Vanlige begreper](https://designsystemet.no/no/best-practices/content-work/terms)

### Skim Reading (Skumlesing)

Write content that's easy to scan:

```tsx
// Good - Scannable structure
<ContentSection title="Priser og betaling">
  <List>
    <List.Item>Gratis for barn under 12 år</List.Item>
    <List.Item>Rabatt for studenter med gyldig ID</List.Item>
    <List.Item>Betaling med kort eller Vipps</List.Item>
  </List>
</ContentSection>

// Bad - Wall of text
<Paragraph>
  Det er gratis for barn under 12 år. Studenter med gyldig ID får rabatt.
  Du kan betale med kort eller Vipps.
</Paragraph>
```

> Reference: [Skumlesing](https://designsystemet.no/no/best-practices/content-work/skim-reading)

## Component Usage Best Practices

### Button Usage

```tsx
// Primary action - one per page section
<Button variant="primary">Send søknad</Button>

// Secondary actions
<Button variant="secondary">Lagre utkast</Button>

// Danger actions
<Button variant="danger">Slett</Button>

// Always provide explicit type
<Button type="submit">Send</Button>
<Button type="button" onClick={handleClick}>Avbryt</Button>
```

### Form Field Patterns

```tsx
// Always use labels
<Field label="E-post" error={errors.email}>
  <Input type="email" required />
</Field>

// Provide help text when needed
<Field
  label="Passord"
  description="Må inneholde minst 8 tegn"
  error={errors.password}
>
  <Input type="password" />
</Field>

// Group related fields
<Fieldset legend="Kontaktinformasjon">
  <Field label="Fornavn">
    <Input />
  </Field>
  <Field label="Etternavn">
    <Input />
  </Field>
</Fieldset>
```

### Error Handling

```tsx
// Form validation errors
<ErrorSummary>
  <ErrorSummary.Heading>Det er 2 feil i skjemaet</ErrorSummary.Heading>
  <ErrorSummary.List>
    <ErrorSummary.Item href="#email">E-postadressen er ugyldig</ErrorSummary.Item>
    <ErrorSummary.Item href="#phone">Telefonnummer mangler</ErrorSummary.Item>
  </ErrorSummary.List>
</ErrorSummary>

// System errors
<Alert variant="danger">
  <Alert.Heading>Kunne ikke lagre</Alert.Heading>
  <Paragraph>
    Prøv igjen om noen minutter. Kontakt support hvis problemet vedvarer.
  </Paragraph>
</Alert>
```

### Loading States

```tsx
// Button loading
<Button loading disabled>
  Lagrer...
</Button>

// Page loading
<Spinner title="Laster innhold..." />

// Skeleton loading
<Skeleton height={200} />

// Content loading with context
<EmptyState
  title="Laster bookinger"
  description="Vennligst vent..."
  icon={<Spinner />}
/>
```

## Performance Best Practices

### Lazy Loading

```tsx
// Lazy load heavy components
const DataTable = lazy(() => import('@xala/ds').then(m => ({ default: m.DataTable })));

// Use Suspense boundary
<Suspense fallback={<Skeleton />}>
  <DataTable data={data} />
</Suspense>
```

### Memoization

```tsx
// Memoize expensive renders
const MemoizedCard = memo(RentalObjectCard);

// Use callback for event handlers
const handleClick = useCallback(() => {
  // handler logic
}, [dependencies]);
```

## Testing Best Practices

### Component Testing

```tsx
// Test accessibility
import { axe } from 'jest-axe';

test('Button has no accessibility violations', async () => {
  const { container } = render(<Button>Click me</Button>);
  const results = await axe(container);
  expect(results).toHaveNoViolations();
});

// Test interactions
test('Button calls onClick when clicked', async () => {
  const handleClick = vi.fn();
  render(<Button onClick={handleClick}>Click me</Button>);

  await userEvent.click(screen.getByRole('button'));
  expect(handleClick).toHaveBeenCalled();
});
```

### Visual Regression

Use Storybook for visual regression testing:

```tsx
// Component.stories.tsx
export const Default: Story = {
  args: {
    children: 'Default state',
  },
};

export const Hover: Story = {
  args: {
    children: 'Hover state',
  },
  parameters: {
    pseudo: { hover: true },
  },
};
```
